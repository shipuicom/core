Upgrading

ship-migrate applies a release's renames to your templates and styles: element tags, CSS custom properties, colour classes, removed inputs, Sass flags and TypeScript class names. What it cannot decide safely, it lists with file and line instead of guessing.

Run it

  1. Commit or stash your work, so the rewrite is one reviewable diff.
  2. Update the package, then do a dry run to see what would change.
  3. Run it for real and read the warnings it prints.
  4. Make the remaining changes by hand from the migration guide.

Every change and every warning comes with its file and line. It also warns at the top when no stylesheet loads @ship-ui/core/styles.

Options

OptionEffect
[folder] or --src <folder>Where to look (default ./src). node_modules, dist and dot-folders are skipped.
--dry-runPrint what would change, write nothing.
--to <version>Apply one release's rules only (default: every known release, in order).
--helpUsage. Any option it doesn't know stops it before it reads a file.

It reads .html, .ts (inline templates and styles), .scss, .sass, .css and .less. Running it twice is safe: the second run changes nothing.

How it stays safe

  • A generic name such as --miw is renamed only inside a rule or on a tag for the component that read it; elsewhere it may be your own variable, so it is reported instead.
  • A colour class like warning is renamed only on the components that had it; the same class on your own elements is reported.
  • Comments, strings and URLs are never rewritten, and a tag is read to its real end, attribute values and Angular bindings included.

0.26: what to do by hand

The script points at most of these; the migration guide has the full list and rename tables.

  • Import @ship-ui/core/styles if you didn't: variant and colour styling now comes from the global stylesheet. See Theming & styles.
  • Single padding tokens (--card-p, --list-p, …) became -py / -px pairs fed by the density tiers.
  • Selectors that relied on a base host class: it is no longer added when a component has no variant.
  • SHIP_CONFIG: alertVariant, cardType and tableType became alert / card / table {{ '{' }} variant {{ '}' }}.
  • sh-list-item-swipe action buttons: .danger / .warning → .error / .warn (old names keep working until 0.27).
