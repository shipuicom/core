Theming & styles

Every component ships its own structure (layout, sizing, states). Colour and variant styling, the "skins", come from one global stylesheet you control: keep what you use, drop what you don't, and set project-wide defaults.

The global stylesheet

Import it once at the top of src/styles.scss. It emits the design tokens (palettes, type scale, spacing, shapes) and the skins every component reads. Without it, colour and variant classes style nothing.

Variants × colours

Sheet components take one of four variants and one of the palettes as a class or input. This is the skin the global stylesheet emits for buttons:

@for (color of colors; track color) { {{ color }} } @for (variant of variants; track variant) { {{ variant }} @for (color of colors; track color) { } }

Keep only what you use

Pass a with (...) block to emit fewer colour classes, fewer variants, or no skin at all for a component. A $ship<Name> flag switches that component's skin only; its structure always ships with the component.

SettingEffect
$shipColorsColour classes every skin emits. Defaults to every palette.
$shipVariantsSheet variants every skin emits: simple outlined flat raised.
$shipSkinsPer component (colors: …, variants: …) overrides of the two lists.
$ship<Name>: falseDrops that component's skin, e.g. $shipChip, $shipToggle.
$shipPalettes, $shipPaletteStepsAdd palettes, or emit fewer palette steps. See Palettes.

Project defaults

SHIP_CONFIG sets the colour, variant, size and modifiers a component uses when the template doesn't say. An input on the element always wins over the config.

Font, size, shape and density

A handful of custom properties on :root retune everything at once. The type scale reads --font-family; rem sizes follow --font-size; corner radii scale with --shape-scale; padding follows the density pair.
