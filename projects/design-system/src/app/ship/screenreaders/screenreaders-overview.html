The sh-screenreader component is a development tool that simulates what assistive technology would announce, following the WCAG/ARIA accessible-name, role and state computation. It transcribes focus moves and aria-live region changes into a floating panel, and can optionally voice them through the browser's SpeechSynthesis API.

Announcements follow the NVDA/VoiceOver phrasing order: name, role, states, value, level or position — for example Accept terms, checkbox, checked or Overview, heading, level 2. The panel removes itself from the accessibility tree (aria-hidden), so it never announces itself.

For automation — e2e tests, devtools debugging, or AI-agent workflows — the service exposes a global window.shipScreenreader handle: say(selector) returns the announcement for an element, expect(selector, phrase) asserts it, focus(selector) focuses and announces, and enable()/log()/clear() drive the transcript. No Angular access required.

The name/role computation is verified in CI against Chromium's real accessibility tree (via CDP) and against a curated subset of the W3C web-platform-tests accname suite; the remaining gaps (CSS generated content, text-transform, embedded controls in labels) are documented in the test fixtures.

It is an approximation for quick feedback loops while building accessible components — not a substitute for testing with real screen readers like NVDA, JAWS or VoiceOver.
