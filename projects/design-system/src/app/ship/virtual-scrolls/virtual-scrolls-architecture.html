How ShipUI virtualizes

Every virtualized surface in ShipUI — sh-virtual-scroll, sh-code, sh-sheet-view and sh-editor — shares one engine. At the bottom sits BlockHeightMap, a pixel-size model; on top of it, ShipVirtualWindow runs the scroll math and exposes the mounted range as signals. The component and the directive are thin DOM adapters over that core, and you can use it directly for anything with an ordered pixel layout.

Only the items inside the viewport (plus an overscan margin) exist in the DOM; spacers stand in for the rest, so the scrollbar geometry matches a fully rendered list.

The component

<sh-virtual-scroll> is the drop-in form: it owns the scroll viewport, measures every projected item with a ResizeObserver, and translates the content to the window's offset. Items are projected with an #item template ref so the component can find and measure them.

The directive

[shVirtualScroll] is the bring-your-own-markup form: put the directive on the element holding your rows, inside a container with overflow: auto, and render only the start()..end() slice yourself. The directive scrolls against the nearest scrollable ancestor (or the host itself when the host scrolls) and owns the spacer padding and the measurement pass (offset deltas after every render). Export it as #vs="shVirtualScroll" to read the window.

The engine: ShipVirtualWindow

ShipVirtualWindow is headless — no DOM, no DI. Feed it scroll positions and measurements; read the window back as signals. This is what to reach for when neither DOM adapter fits: canvas rows, table axes, editor blocks.

The pixel model: BlockHeightMap

Sizes are "distance to the next item's top", so margins and margin-collapse are inside the numbers and the prefix sums match real layout. Estimates come from a rolling average of what has been measured — locked after 32 measurements to keep the model deterministic.

The editors

sh-code windows lines on a ShipVirtualWindow (uniform line height — no per-line measurement pass). sh-editor sits directly on BlockHeightMap: its window pass is interleaved with DOM reconciliation, scroll-anchoring compensation and caret repainting, so the signal wrapper would only add indirection there.
