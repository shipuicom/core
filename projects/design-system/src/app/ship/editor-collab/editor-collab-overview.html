Overview

@ship-ui/core/ship-editor-collab turns any sh-editor into a shared document. It builds on the editor's operation model: every edit is a serializable op, concurrent edits converge through the fuzz-verified transformOp / rebaseOp algebra, and remote edits never enter your local undo history.

  • shCollab — one attribute on sh-editor : provides the session, attaches it, mounts the cursor overlay and tears it all down with the editor.
  • ShipEditorCollab — the session: broadcasts your edits, rebases and applies everyone else's.
  • CollabTransport — any message pipe; BroadcastChannelTransport (same-origin windows, no server) and WebSocketTransport (server relay) ship built in.
  • <sh-editor-remote-cursors> — peer carets, selections and name tags.

  1. Click Open second window and place the windows side by side.
  2. Type in either window — edits and the colored remote caret appear live in the other.
  3. Flip on Fuzz edits in one window, then keep typing in the other while random edits storm the first. When the checksums in both windows match, the documents converged.

How it works

  • Session. shCollab provides a ShipEditorCollab on the editor and attaches it to the editor's engine after first render. From then on every local transaction is broadcast as an EditorOp tagged with a sequence number and the sender's view of everyone else's sequence.
  • Convergence. An incoming op is rebased over any local ops the sender had not yet seen ( rebaseOp ), then applied with applyRemoteOperation , which maps your caret across the change and keeps remote edits out of your undo stack. The checksum badge in the demo is the proof: it matches across windows after the fuzz storm.
  • Presence. Selections are broadcast (throttled) with each op; the directive mounts <sh-editor-remote-cursors> in the editor body to paint them, and exposes collab.peers() for badges like the ones above.
  • Joining late. A new window sends join ; any existing peer answers with a snapshot of the document, and the joiner starts from there.

Behavior guarantees

Undo only ever removes your edits; late joiners receive a snapshot from an existing peer; and the op algebra ( transformOp , rebaseOp , applyOp ) is exported for integrations that need to rebase server-side.
