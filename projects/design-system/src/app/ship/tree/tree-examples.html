A complete explorer built around the tree: a filter box narrows the list to matching files and their ancestors, getIcon picks an icon per file extension, and selectedId drives a detail pane with a breadcrumb, metadata, rename, and delete. New files and folders land in the selected folder.

Because filtering derives a new list, the tree is bound with [items] plus (itemsChange) instead of two-way binding, so folder toggles are copied back onto the source list rather than overwriting it.

Integrate the tree component with createTreeSortableManager to enable premium, VSCode-style interactive drag-and-drop. Also shown on the Sortables examples page.

The tree is fully keyboard operable: Tab focuses the tree, the arrow keys move focus and expand or collapse folders, Enter selects, and typing a letter jumps to the next matching node. With a sortable manager, Space picks the focused node up, ArrowUp/ArrowDown move it, Space drops it, and Escape cancels and returns it to its original position.

Define a custom node layout inside the #nodeTemplate child element. This example maps custom property keys, resolves custom icons, displays status badges, and supports deleting elements.

The tree doesn't require any specific data shape. By default it reads item.id and item.parentId, but you can point it at any field names by passing accessor functions to getId and getParentId — here the data uses uuid and ownerUuid instead. The same pattern applies to getName and isFolder.
