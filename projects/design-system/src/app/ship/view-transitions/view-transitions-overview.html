Overview

[shViewTransition] turns a router-outlet into an iOS-style navigation stack using the browser's View Transition API : pages slide, push back, fade or scale as the router swaps them. The leaving and entering page each get their own animation, the direction (forward or back) is detected for you, and the pages are clipped to the outlet's parent so nothing bleeds outside a phone frame or a card.

See the live demo under Examples, it uses routed tabs plus a detail page.

Setup

Add the router feature and the provider. The provider requires a default so no keyframes are bundled unless you import them; start from a preset such as shipIosTransitions , shipSheetTransitions or shipFadeTransitions .

Animating an outlet

Put the directive on any router-outlet . Without a value it plays the provider defaults. Pass a spec to choose the in (entering page) and out (leaving page) animation and an optional back pair. Nested outlets can each have their own spec.

Provider config

The config sets the forward and back pairs, duration and easing. Animations are referenced by import, so bundlers drop the ones you never use. List extra animations under animations to make them referencable by name from templates.

Direction

Browser back is a back transition. Otherwise a deeper URL is forward, a shallower one is back, and sibling routes (tabs) go left-to-right by their order in the route config. Override per navigation through the info navigation extra, or opt a route out with route data.

Custom animations

createViewTransition() wraps a keyframe body. The keyframes are injected the first time an outlet uses them, so custom and built-in animations cost the same: nothing until used. layer: 'below' draws that page under the other one, which the push-back style animations rely on.

Swipe back

Add swipeBack to the outlet and dragging from the left edge of the frame scrubs a back navigation with the finger, like iOS. Where the finger lets go decides: past halfway completes the back navigation, before it the page stays. While a swipe is in flight every other click, key and pointer is swallowed so nothing else can start a navigation. Under the hood the router really navigates back and the transition's animations are paused and seeked; a cancel scrubs them back to the start, steps history forward while the transition still covers the page, and only then lets go, so nothing flashes.

Good to know

Users who prefer reduced motion get an instant swap. Route reuse (navigating between params of the same route) does not swap the component, so nothing animates; use separate routes or a custom RouteReuseStrategy . Clipping to the parent relies on nested view transition groups; browsers without them still animate, just without the clip.
